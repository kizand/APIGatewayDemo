# API Gateway & Microservices Architecture Demo

Реализация отказоустойчивого API Gateway (шлюза) на базе Spring Boot 4.1.x (Java 25) и реактивного стека WebFlux. 
Этот небольшой учебный проект демонстрирует централизованную маршрутизацию, динамическую модификацию заголовков и локальную JWT-аутентификацию/авторизацию пользователей по ролям без использования внешних провайдеров (Keycloak/Auth0).


## Архитектура системы

Проект реализован в виде многомодульного приложения:
• API Gateway (Порт: 8080) — единая точка входа. Направляет трафик, проверяет токены, добавляет системные заголовки.
• UserService (Порт: 8081) — блокирующий микросервис (Tomcat) для управления пользователями.
• OrderService (Порт: 8082) — блокирующий микросервис (Tomcat) для обработки заказов.


## Технологический стек

• Java 25
• Spring Boot 4.1.1
• Spring WebFlux (для API Gateway)
• Spring Web MVC (для микросервисов)
• io.jsonwebtoken (jjwt) 0.12.5 (для локальной валидации JWT)
• Spring Boot Actuator


## Реализованная бизнес-логика и правила доступа

1. Маршрутизация: Запросы на /users/** пересылаются на http://localhost:8081, запросы на /orders/** — на http://localhost:8082.
2. Модификация запросов (Фильтры): При маршрутизации в OrderService шлюз автоматически добавляет заголовок X-Request-ID: 12345.
3. Аутентификация: Доступ к системе закрыт для неавторизованных пользователей (HTTP 401 Unauthorized). Требуется передача Bearer <JWT_TOKEN>.
4. Авторизация (Разделение прав):
   • Пользователи с ролью USER имеют доступ только к GET-запросам на /users/**. Попытка сделать POST на /orders/** возвращает HTTP 403 Forbidden.
   • Пользователи с ролью ADMIN имеют полный доступ, включая выполнение POST-запросов на /orders/**.


## Инструкция по запуску и тестированию

1. Генерация токенов

Для тестирования безопасности сгенерируйте токены на сайте jwt.io (алгоритм HS256):
• В поле Secret вставьте ключ: mySecretKeyForJwtAuthentication2026!!! (убедитесь, что галочка base64 выключена).
• В поле Payload для проверки пользователя вставьте:

{
"sub": "1234567890",
"name": "John Doe",
"role": "USER"
}

Для проверки администратора замените "role": "USER" на "role": "ADMIN". Скопируйте получившийся Encoded токен из левого окна.


2. Порядок запуска приложений в IntelliJ IDEA

Запустите класс ApiGatewayDemoApplication (модуль шлюза).
Запустите класс UserServiceApplication (порт 8081).
Запустите класс OrderServiceApplication (порт 8082).

3. Тестовые сценарии для Postman

Сценарий 1: Проверка аутентификации (Без токена)
• Запрос: GET http://localhost:8080/users/info
• Результат: HTTP 401 Unauthorized.

Сценарий 2: Успешный доступ пользователя к своим данным
• Запрос: GET http://localhost:8080/users/info
• Авторизация: Тип Bearer Token, вставьте токен USER.
• Результат: HTTP 200 OK. Текст: "Успех! Ответ напрямую из UserService..."

Сценарий 3: Попытка пользователя нарушить права доступа
• Запрос: POST http://localhost:8080/orders/create
• Авторизация: Тип Bearer Token, вставьте токен USER.
• Результат: HTTP 403 Forbidden.

Сценарий 4: Успешное создание заказа Администратором
• Запрос: POST http://localhost:8080/orders/create
• Авторизация: Тип Bearer Token, вставьте токен ADMIN.
• Результат: HTTP 200 OK. Текст: "Заказ успешно создан в OrderService... правами Администратора!"
